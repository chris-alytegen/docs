Entries below describe sandbox (`https://app.alytegen.com`) unless explicitly
marked planned or not enabled.

## October 2026

### Attest-only keys in the console

Enabled organizations can choose **attest verified customers only** in
**API keys**. The key has only `mandates:attest`. If enablement is removed,
the option disappears; a selected option is cleared and minting waits for an
explicit scope choice. The API-key list now includes `attestAvailable` for
the signed-in organization. [Guide and REST example →](/guides/console-api-keys)

### Consent confirmation by email link (planned)

The approved replacement for the verification code uses an emailed link to
an Alyte page that shows and executes stored terms. It is **not enabled**;
the API core is under review, and the pages, mail delivery and new-card flow
remain follow-up work. SDK 0.4.0 and the current step-up flow still apply.
[Availability and planned contract →](/guides/consent-confirmation)

### Saved-card setup checks

Stripe card setup now verifies off-session setup and the card's customer
association before saving it. Retrying verification after a successful setup
reuses that setup. `card_preparation_unavailable` is retryable;
`card_not_chargeable` and `card_customer_mismatch` need the buyer to correct
the saved-card setup. [Errors →](/guides/errors)

### Buy inside your chat with the browser SDK

`@alytegen/sdk` 0.4.0 adds `@alytegen/sdk/browser`: your page exchanges a minted
session for a bounded bearer held in memory, opens Alyte's consent view inline
when the buyer needs an agent (verification and card entry happen inside it), and
buys or queues within the permission — no redirect, no cookies. Sign-in and
verification routes are refused to partner origins; the bounded bearer cannot
create or widen spending authority. [Details →](/guides/chat-consent) ·
[Browser access and CORS →](/guides/browser-api)

### Up to three embed origins

`embedOrigin` accepts up to three bare origins (space- or comma-separated), so
production and staging can both frame the authorize page and call the buyer API.
`http` is accepted for `localhost` only. [Details →](/guides/embedded-authorize)

### Attested consent for contracted merchants

Merchants Alyte staff enable under contract can mint with `merchantAttested: true`
on a `mandates:attest` key: the buyer's permission is created within staff-set
ceilings without the emailed code and shows "Set up by *shop*". Everyone else is
refused with `403 merchant_consent_not_enabled`. [Details →](/guides/buyer-sessions)

### Buyers verify their email before granting an agent spending power

Sessions you mint with `buyerSessions.mint` are now **bounded**. They can act
inside authority the buyer already granted, but saving a card, creating an
agent, granting a mandate, changing an agent's card or raising a card's spending
cap first needs a 6-digit
code emailed to the buyer. The authorize page asks for it; your integration
does not change. Test with inboxes you can read.
[Details →](/guides/buyer-sessions)

### Tier restrictions are accepted on create

`POST /v1/integration/tiers` now saves `onSaleStart`, `onSaleEnd`,
`maxQtyPerPurchase`, `sellable`, `allowedGeos` and `allowedSchemes` in the same
write as the tier. Unknown fields are refused with `400` instead of being
dropped. [Details →](/guides/quickstart)

### The buyer pages speak six languages

The authorize page and buyer screens are available in English, German, Spanish,
French, Hungarian and Brazilian Portuguese. Pass `lang` when you mint a session
to choose one; otherwise the buyer's own choice or browser language applies.
The non-English text is a first draft pending native review: report anything
that reads wrong.

### Rate limits tell you when to retry

A `429` now carries `code: "rate_limited"`, a `retryAfter` value in seconds and a
matching `Retry-After` header. [Errors →](/guides/errors)

### Card setup accepts cards only

The card-capture step now offers card payment methods only. Saved cards are
also tied to the shop and payment connection they were saved for; using one
elsewhere is refused with `409 instrument_provider_mismatch`.

### Payments can be pending

Confirm can answer `202` when the shop's payment provider confirms
asynchronously. Do not submit the payment again; the purchase completes or is
released when the provider's confirmation arrives.
[Agent buy path →](/guides/agent-buy)

### Adyen (coming to sandbox)

Merchant setup can now hold an Adyen sandbox connection, and Alyte can save
Adyen cards and complete Adyen purchases from verified provider evidence. It is
**not switched on in sandbox yet**: Stripe remains the provider to test with.

### Public SDK

`@alytegen/sdk` is on npm (MIT): `npm install @alytegen/sdk`.
